### 1.2 Live defects found

**a) CLI is not runnable from a clean clone without an undocumented install.**
`cli/` depends on `@core-builds/core` via `file:../packages/core`. Before
`npm install` inside `cli/`, *all 75 CLI tests fail* with
`ERR_MODULE_NOT_FOUND`. Anyone evaluating the CLI from source (or a CI job that
installs the wrong workspace) sees a dead tool. README should state the install
step or the repo should gain a root workspaces `package.json`.

**b) Open issue #770 — AIOStreams contract drift, now 3 days stale and growing.**
The aios-regen contract was pinned 2026-09-26 at upstream commit `00fb93a`.
Upstream has since shipped **v2.35.0 → v2.35.3** (104 commits ahead of the pin,
verified via GitHub compare). The drift detector has fired **7 times** on the
open issue with no re-pin. Relevant upstream changes inside the drift window:

| Upstream change (v2.35.x) | Impact on Core Builds |
|---|---|
| `presets/newznab.ts` +56/−7 and `builtins/base/nab/api.ts` (hash-fallback bug fix, missing-infohash warning) | **Directly touches the NAB layer 19 of our templates use** (see 1.2-c) |
| New built-in addon **TsukiHime** (`presets/tsukihime.ts`, 111 lines) | Contract preset count changes; anime-capable source our templates don't know about |

| Formatter: `::unique`, `{stream.site}`, `audioTracks`/`subtitleTracks`, user lists | New capabilities our "19 formatters" story doesn't offer yet |
| Failover: only-same-release toggle (#1319); filter: block pre-release-date results (#1312); cached autoplay attribute | Features users will ask for; #1312 directly attacks the junk-rate problem |

`configurator/UPSTREAM.pin` (v2.34.1) is likewise one minor behind. Neither pin
is broken *today* — but the product's core promise is "we track AIOStreams for
you", and right now the tracker is behind the thing it tracks.

**Lane attribution (corrected in addendum):** the strict-matching cluster splits
into lanes. The three dual-core templates (`core-nexus-4k-dual-core`,
`core-nexus-4k-essential-dual-core`, `core-nexus-dual-core-1080p`) live in
`Templates/Torbox/Deprecated/` — frozen by convention, not fixed in place.
`prism-torbox-essential-1080p`, `auburn-tiger-rb3` and `rb3-torbox-pro-rd-hybrid`
are **community** templates under `Community-Templates/` — third-party content
Core Builds warns about but does not rewrite. The only active-lane remediation
in this cluster was `core-nexus-usenet-4k` (0Cached fallback), fixed same-day.
**The real exposure was shipping, not the files themselves:** finding 1.2-g
shows the deprecated dual-core builds were still being preloaded onto hosts.
The combination (exact + strict year + strict S/E) is the exact recipe for the
#1 community complaint pattern — *install works, search returns nothing* — the
same family as the v2.4.0 `onlyShowCachedStreams: true` bug; the validator now
hard-fails it in active Core lanes (addendum).

**d) Known upstream AIOStreams bugs that currently distort our quality claims.**
Open upstream issues that degrade behaviour our templates depend on (checked
2026-09-29): NZBHydra streams failing to resolve via TorBox ("same as #891" —
our hybrid templates' usenet lane), episode-title matching becoming a no-op
when Cinemeta/TVDB dates disagree, addon timeouts starting before metadata
resolution completes, parser gaps (squashed AAC tags return null audio
codec/channels on 55k+ releases; HDDVD Remux misdetected as DVD REMUX), and the
Flix-Streams preset being outdated. None are our bugs, but our sort ranks and
junk filters consume their output, so "Core Builds ranked it badly" is what the
user sees.

**e) The benchmark harness is sound but has produced zero live evidence.**
`selftest.py` passes completely (sanitizer gaps, mutation replay, directive
resolution all covered). But `reports/TEMPLATE-BENCHMARK.md` states plainly:
**0 live runs, 0 snapshots — blocked on an instance URL + debrid credentials.**
Meanwhile `competitor-analysis.md` (2026-09-06) makes comparative claims
("Core Builds already wins on curation") from static config inspection only.
We currently *cannot demonstrate* that we beat rivals at the only thing that
matters to users: playable results on real titles. That is the single biggest
audit gap in the repo.

**f) Minor.** `STATUS.md` is retired with no automated replacement (Preflight is
manual); corpus verification for the benchmark completed only 6/30 IDs in the

**g) Host-preload collection served 15 deprecated templates — found during fix
execution (addendum).** `scripts/sync_template_collection.py` excluded
`Legacy`/`Deprecated` lanes by checking **only the first path part**, while the

them the strict-matching dual-core templates of finding 1.2-c, i.e. hosts
pinning `TEMPLATE_URLS` were offering users the exact configs most likely to
return zero streams. The collection also carried a duplicated
`core-nexus-4k-dual-core` id. Fixed same-day: lane check reads every path
part; regenerated collection has 50 entries and no duplicate ids.

## Part 2 — Competitive research (why "ours" loses where it loses)

Sources: r/StremioAddons and r/CoreBuilds threads (2026), upstream AIOStreams
releases/issues, rival template downloads, and third-party comparisons.

### 2.1 The structural deficit: we sell configs for a wrapper, rivals sell addons

Core Builds is a layer *on* AIOStreams; every AIOStreams weakness is inherited
as-is and attributed to us:

| Weakness (user-reported) | Evidence | Why it hurts us specifically |
|---|---|---|
| **Slower than standalone addons** — "it takes more time to give me results than having separate addons… I don't see the added value" | r/StremioAddons "So… I tried AIOStreams" | Our heavy templates (5+ enabled addons, 107 regexes, 23 SELs) maximise latency; AIOStreams returns one aggregated body only when the slowest addon/time budget completes |
| **Single point of failure** — public instance down = whole addon dead; users report "no streams found" cured only by re-installing against another instance | multiple threads; viren_7's reinstall anecdote | Our templates are host-agnostic in theory but host-allowlisted in practice (TorBox Search API, SEL sync gating, SEL length limits) |
| **Cache lying** — "RD media has not been cached" despite RD+ display; cache detection is a ~95% estimate since RD removed the real API | r/StremioAddons "reliable for everyone… but for me it's a mess" | Our cache-first sort *assumes* cache flags are truthful; when they aren't, #1 result fails to play — the worst possible failure |
| **Duplicates & playback errors** | same thread (8–10 repeats of one stream) | Upstream only just fixed repost-suffix dedup in v2.35.1; we pin v2.34.1 |

Meanwhile the standalone competition solved exactly these:
**Comet** — cache-first lookup (fastest first results), built-in debrid proxy
(no multi-device IP errors), CometNet shared metadata (rising cache hit rates),
self-hosting, Kodi client. **Torrentio** — one-field setup, broadest scraping
for uncached/obscure titles. **MediaFusion** — metadata/quality accuracy.
2026 third-party comparisons consistently rank a *stack* (Torrentio primary,
Comet fallback, MediaFusion tertiary) and recommend AIOStreams mainly for power
users — i.e., the market default is "several simple addons", not "one tuned
template". Our answer to that (device-aware profiles, host gating, failover)
is real but invisible in a 30-second comparison.

### 2.2 The distribution deficit: rival *templates* out-UX us at import time

The direct competitors are not just addons but other template packs — and the
community names them: on "best setup for TorBox" threads, users recommend
**Tamtaro's Complete** and **luckynumb3rs' "Streaming Perfect Setup"** (a
Tamtaro derivative) over alternatives. Downloading the latter (v2.0.10) shows
why: it is a **wizard template** — guided inputs at import time (preferred
languages multi-select with a hard-filter toggle, formatter style choice,
P2P/HTTP lane toggles, subtitle languages), building a full multi-lane config
in-flow. Our own `competitor-analysis.md` measured the scale: Tamtaro ships
**549 wizard directives across 25 top-level fields**; we ship **zero** —
our 90 templates are static configs whose personalisation lives in the
external configurator.

Consequence: a user browsing AIOStreams' template directory gets a tailored
config from rivals without leaving the page; from us they get a fixed config
and a link to another website. Our configurator is objectively deeper
(device profiles, host-compat gating, update/diff/cherry-pick) — but it is
one click further away, and distribution beats depth for first impressions.
Tamtaro also syncs a **stream-expression URL**; we sync 0/90 (gated by
instance env, but we don't even attempt it).

### 2.3 The language/region blind spot

A documented complaint against the Vidhin05 ranked-regex set — which **64 of
our 90 templates sync** — is that its "Bad Dual Groups" rule silently blocks
legitimate PT-BR release groups (alfaHD, PTHome, C.A.A, GUEIRA, XiQUEXiQUE…).
Our drift watcher tracks that source for *changes* but not for *content
harm*; our own 107-pattern set has no PT-BR handling either. For non-English
users this reads as "Core Builds finds nothing", and it is invisible in
English-language testing. Related upstream history: Portuguese false-positives
("por" in Spanish filenames), missing PT-BR subtitle variants — a recurring
theme we have never instrumented.

### 2.4 Honest ledger — where we genuinely lead

- **Curation depth:** 107 ranked regexes + 23 SELs vs rivals' 0–10 (measured, 2026-09-06).
- **Engineering hygiene:** ~1,100 automated tests across surfaces; rivals ship none. Secret scanning, CSP, DO-backed paste store, rate-limited worker.
- **Host compatibility gating** (grey-out + strip of rejected options) — no rival template does this.
- **Update path** (import-live-config → diff → cherry-pick) — unique.
- **Repair discipline:** previously published bugs and gaps (eses(), dead keys, NZB failover) verifiably fixed.

The gap is not quality of engineering; it is **time-to-first-playable-result,
import-time personalisation, and absence of public proof**.

### 2.5 Root-cause ranking: why "ours is faulty"

1. **Silent zero-result failures** — the strict-matching cluster (1.2-c) plus
   historically `onlyShowCachedStreams`. Matches the dominant community
   complaint. Fixable entirely inside this repo.
2. **Latency** — heavy multi-addon templates on a wrapper that aggregates
   serially; rivals trim or bypass. Mitigable (streamPool, early-exit tuning,
   per-device addon sets) but bounded by upstream architecture.
3. **Silent lane death** — TorBox Search allowlisting makes the usenet lane
   vanish without error on non-approved hosts (the legacy-NAB-keys half of the
   original finding turned out to be confined to the frozen Legacy lane —
   corrected in addendum).
4. **Fragility at limits** — 8 payloads near the 102,400 B save cap, 148 SELs
   near the 3,000-char host cap: every future feature fights the ceiling.
5. **Upstream lag** — pins behind v2.35.x: we miss cache-honesty fixes
   (dedup repost suffixes), junk filters (pre-release-date block), and new
   sources (TsukiHime) that rivals' next update will advertise.
6. **No evidence** — the benchmark harness exists and self-tests green, but
   has never run live; superiority claims are config-inspection only. Without
   numbers we cannot even confirm *which* of 1–5 matters most.
