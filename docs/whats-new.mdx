## Configurator v3.18 (Oct 22 2026)

<CardGroup cols={2}>
  <Card title="Templates save on AIOStreams 2.36 again" icon="sparkles">
    AIOStreams 2.36.0 removed the AIOSubtitle addon and refuses any config that includes it, and 52 Core Builds templates did, so every host on 2.36 (seven of the eight public ones, ElfHosted included) refused them with “AIO Subtitle has been removed”. They now use OpenSubtitles v3+, the configurator’s default since 3.16. Re-import your template to pick up the fix.
  </Card>
  <Card title="AIOSubtitle leaves Fine-Tune" icon="bolt">
    its addon is no longer hosted. A saved AIOSubtitle choice moves to OpenSubtitles v3+ and your other subtitle sources stay; a config you import or update has it removed before install.
  </Card>
  <Card title="Retired addons are never sent" icon="shield-check">
    AIOStreams 2.36.0 retired 15 addons, among them Argentina TV, USA TV, Nuvio Streams, Debridio WatchTower and AIOSubtitle. Argentina TV is no longer offered, and any of the 15 found in an imported or updated config is dropped before install instead of getting it refused.
  </Card>
  <Card title="Anime Tosho moves to its live feed" icon="sliders">
    the original Anime Tosho stopped taking releases on May 9 and its feed shuts down this month, so Anime builds were about to lose their anime source. Anime and Movies + Anime builds now use the community continuation (anime-tosho-new in AIOStreams 2.36), as do the nine Anime and Labs templates. It needs AIOStreams 2.36.0, which seven of the eight public hosts run: builds carrying it are not sent to Omni’s (2.35.9, now marked legacy), and picking the 2.35.7 target keeps the old source.
  </Card>
  <Card title="Pinned to AIOStreams 2.36.0" icon="gauge">
    the schema the configurator checks against, and its default compatibility target, move from 2.35.7 to 2.36.0, the release ElfHosted and most hosts run. Sessions saved on the old 2.35.7 default move with it; a target you picked yourself is kept.
  </Card>
  <Card title="Stream proxy that works" icon="wand">
    Fine-Tune has a Stream Proxy section again, and AIOStreams now applies it: MediaFlow Proxy, StremThru or the AIOStreams built-in proxy, with its address, password and the services to route. The old toggle sent no address and no on switch, so it never proxied anything. AIOStreams checks the proxy when you save; if it cannot reach it, the configurator says so and offers to turn it off. The password stays on your device and in the config you install, never in share links.
  </Card>
  <Card title="Updates keep your proxy" icon="layers">
    installing after importing your live config replaced a proxy you had set up in AIOStreams with an empty one. It is now carried over, and updating from a Core Builds template keeps yours.
  </Card>
  <Card title="Sources serve only streams" icon="bug">
    AIOStreams runs a source with everything it supports unless the config narrows it, and the configurator’s limit never reached it. Torrentio, StremThru Store and Peerflix added debrid-library catalogs to your home screen, Sootio and Flix-Streams catalogs, YaStream catalogs and subtitles. They now serve streams only, and TMDB Collections serves only its catalogs.
  </Card>
  <Card title="Live TV shows its channels" icon="sparkles">
    USA TV Next was limited to streams, but its channels are browsed in catalogs, so switching it on added nothing to browse. It keeps its catalogs now. Content Deep Dive is sent as the stream companion it is, and Doctor Who Universe keeps its streams.
  </Card>
  <Card title="Template directory versions are current" icon="bolt">
    the docs page showed 22 of its 43 templates with old version numbers (Windows Ultrawide read v0.2.4 against v0.2.13). Every heading now updates with its template.
  </Card>
  <Card title="The unlinked V3 prototype is gone" icon="shield-check">
    an unfinished second configurator was still published at /configurator/rebuild/ though nothing linked to it. It is removed, and twelve dated audit and plan documents moved from the repository root into archive/.
  </Card>
</CardGroup>

## Configurator v3.17 (Oct 22 2026)

<CardGroup cols={2}>
  <Card title="ElfHosted saves refused" icon="sparkles">
    fixed. Since about Oct 15 every config exported from the configurator was refused with '1 regexes are not allowed'. Vidhin05 added the SumVision release group to one of the two Generated Dynamic HDR patterns, and hosts accept a regex only when it matches their allowlist character for character, so the copy every build carried stopped counting as allowed. Removing that row let a save through, which is how it was reported. The pattern is now re-derived verbatim from upstream across the configurator, the CLI, the shared filter files and 43 templates, each of which bumps so the update banner offers the fixed copy; the same pass carries the other upstream edit (SiCFoI added to LQ (Release Title) (Radarr)). Checked against a real AIOStreams with ElfHosted's current rules: 0 of 388 builds saved before, 388 of 388 after. On Oct 22 Vidhin05 edited Radarr Web T1–T3, Sonarr Web T2, FLUX and TrueHD Exclude Groups (monkee and CMRG added, SiGMA and DON dropped, FLUX made case-sensitive). Every build that carries the inline regex list shipped five strings ElfHosted no longer allows, so saves were refused again. All copies now match upstream character for character. The re-sync tool had skipped the FLUX edit because it ignored regex flags, and it never covered the CLI's own copies, where an outdated BR-DISK filter had also been left behind; both are fixed and now checked.
  </Card>
  <Card title="Core Stable is now the default" icon="bolt">
    every build starts on Core Stable, the profile Express already used: predictable fetching, minimal rules and a clean stream card. Choosing the Apex IQR or Apex Mixed engine still selects Advanced or Labs, and a profile you pick yourself is kept. A saved session left on automatic moves from Balanced to Core Stable on its next export; pick Balanced in Review to keep the old behaviour. The landing page now says which profile you start on, instead of promising a preload Core Stable does not do.
  </Card>
  <Card title="Choices Core Stable cannot use now say so" icon="shield-check">
    Core Stable replaces the stream card, the sort order and auto-play, so choosing a card style, Library Boost or an auto-play method used to change nothing. On an automatic build that choice now moves you to Balanced, which honours it, and a notice says why; a profile you picked yourself is never overridden. The foreign-language filter and preloading run only on Advanced and Labs, and now say that instead of silently doing nothing. The stream pool, which sizes fetching only Advanced and Labs do, is hidden on the quick-setup finish screen under Core Stable.
  </Card>
  <Card title="Bandwidth cap works" icon="sliders">
    the Mbps box in Fine-Tune accepted a number and threw it away: nothing stored it, so the bitrate limit never applied. Typing your speed now caps bitrate at 80% of it on every profile, as the box always said.
  </Card>
  <Card title="Express installs to WuPlay or another app show their result" icon="gauge">
    after the install, the manifest link opened underneath the Express panel, so it looked as if nothing had happened. Express now closes first and the link appears on top.
  </Card>
  <Card title="Resolution First works on Core Stable" icon="wand">
    Core Stable used its own fixed sort order and ignored the toggle. It now puts resolution first when you turn it on; Quality First still wins if both are on, as on every other profile. The CLI also stops ignoring Quality First on Core Stable builds.
  </Card>
  <Card title="Hide 4K and Hide Dolby Vision work on every profile" icon="layers">
    both were written only as stream rules, which Core Stable and Balanced replace with their own, so on the default build the toggles did nothing. They now use AIOStreams' native resolution and visual-tag filters, which every profile keeps.
  </Card>
  <Card title="Core Stable keeps the sources you chose" icon="bug">
    it trims scrapers to a lean set, but now keeps MediaFusion when Seedr is selected (its only supporter) and AnimeTosho for Anime content, so neither choice can end up with no source at all.
  </Card>
  <Card title="Valid stream rules are no longer reported as blocked" icon="sparkles">
    the host check and the Template Inspector marked any rule using not() as refused by ElfHosted and ForTheWeak. AIOStreams accepts not() on every host. The Inspector's one-click repair rewrote not( as negate(, which needs two stream lists and always fails, so it broke the rules it claimed to fix. Both are gone, along with a warning that a config without the Vidhin05 link 'may not be whitelisted': hosts check each pattern against their own list, whatever links the config carries.
  </Card>
  <Card title="Family setup says what it really does" icon="bolt">
    the guided setup promised 'age gates on from day one', but AIOStreams cannot filter by age rating. The family path sets up a separate kids profile, a PIN and an adult-title filter, and now says exactly that. The unused age-rating setting is removed.
  </Card>
  <Card title="Stream Proxy toggle removed" icon="shield-check">
    it never proxied anything. AIOStreams proxies only when it has a MediaFlow address and password, which the builder never asked for, so the toggle just listed service names. Set a proxy up in AIOStreams itself.
  </Card>
  <Card title="Exports drop two fields AIOStreams never read" icon="sliders">
    presets carried a resources list beside their options, which AIOStreams strips on save (it reads options.resources), and StremThru Store carried a multiple-instances option only StremThru Torz reads. AIOStreams runs these configs exactly as before.
  </Card>
  <Card title="Tools page links open the right screen" icon="gauge">
    Health Score, Troubleshooter and the full changelog link all landed on the configurator home, because the site root redirects without keeping the #section. They now link straight to the configurator, and #changelog opens the changelog.
  </Card>
  <Card title="The drift watcher now names the entry that broke" icon="wand">
    it opened an issue on Oct 15 but listed two other changes. Upstream gives both Generated Dynamic HDR patterns the same name, and the watcher keyed entries by name alone, so the second hid any change to the first. Repeated names are now told apart, and an issue says when a changed pattern is one every generated config ships, which means saves are being refused already. The save test's copy of ElfHosted's allowlist was also two weeks stale, still holding the old text, which is why it stayed green; it is refreshed.
  </Card>
  <Card title="About 1,800 lines of dead code removed" icon="layers">
    an install modal nothing opened, a Quick Start overlay no button reached, six leftover patch notes, six unused debug scripts, an unused catalog module, about 300 style rules nothing matched (22 KB), and handlers for buttons that no longer exist. The Changelog and template-diff dialogs are now announced to screen readers as dialogs.
  </Card>
</CardGroup>

## Configurator v3.16 (Oct 3 2026)

<CardGroup cols={2}>
  <Card title="Builds save again: subtitles now default to OpenSubtitles v3+" icon="sparkles">
    AIOSubtitle, the subtitle source every build used by default, now takes about 12 seconds to answer. AIOStreams loads every add-on before it saves, so hosts refused the whole save with 'Failed to fetch manifest for AIOSubtitle: 502 - Bad Gateway'. New builds use OpenSubtitles v3+, which answers in under a second, and saved sessions still on the old default move over automatically. AIOSubtitle stays available, labelled as slow.
  </Card>
  <Card title="SubDL without a key no longer blocks the save" icon="bolt">
    AIOStreams requires a SubDL API key, but the configurator included SubDL even when the key field was empty, and the save was refused. SubDL is now only added once a key is entered; until then the build uses OpenSubtitles v3+, so it always has subtitles.
  </Card>
</CardGroup>
