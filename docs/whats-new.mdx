# What's New in the Configurator

This page is regenerated from `configurator/src/data/changelog.js` by `scripts/sync-docs.py`, so it always reflects the latest shipped configurator version (currently **v3.12**).

For the template-suite release log, see the [Changelog](https://corebuilds-docs.docsalot.dev/changelog).

## Configurator v3.12 (Sep 26 2026)

<CardGroup cols={2}>
  <Card title="Fleet re-audit" icon="sparkles">
    every public host re-checked against its own status endpoint. Seven of the eight run AIOStreams 2.34.1 (six on the stable build, Viren's on its nightly); Omni's is the only 2.33.2 holdout, over six weeks behind. The schema pin, the default compatibility target and the host registry all move to 2.34.1 together, and the 2.34.1 contract was verified byte-identical to 2.34.0 in every generated file, so nothing you generate changes shape. Two corrections fell out of the audit: ATBP and Wizaardd both report regexAccess `all`, not `trusted`, so their offline defaults now say so — the live probe still wins whenever it can reach the host.
  </Card>
  <Card title="Dead settings stop being emitted, not just stripped" icon="bolt">
    v3.0 found six settings Core Builds emitted that AIOStreams never defined (maxResults, maxResultsPerResolution, seadexBestOnly, excludedStreamSources, enhanceResults, minSeeders) and began removing them at the export gate. The generators kept writing them anyway, relying on the gate to clean up. They no longer write them at all, and the native-filters policy that wrote the dead `excludedStreamSources` now writes the live `excludedStreamTypes` instead — Stable and Balanced output newly, actually excludes YouTube-type streams rather than carrying a key the host ignored. The 55 checked-in templates that carried the dead keys are cleaned (about 8 KB of payload that was stripped on every save), and the guides that described the dead keys as working now describe what the host really reads.
  </Card>
  <Card title="TorBox Search preset is allowlisted, not dead" icon="shield-check">
    the Apex, Hybrid and several Personal and Device templates ship an enabled preset pointed at TorBox's Search API, and the validator called that endpoint shut down. It is not down; TorBox restricts it to allowlisted caller hosts, so it resolves on approved managed hosts and silently times out everywhere else, which reads as slow or missing Usenet results with no error. The warning now says that and points at two new troubleshooting entries: the allowlist (with the remedy — move hosts, or swap in a personal indexer) and the separate TorBox CDN routing advisory, where some hosts need the CDN set manually for AIOStreams-installed addons.
  </Card>
  <Card title="Failover replaces NZB Failover, and two save rejections go with it" icon="sliders">
    AIOStreams renamed nzbFailover to the generic failover (Usenet plus debrid) and migrates the old spelling before validating, passing position through blindly. Core Builds emitted two positions outside the new enum: the before-torrents option wrote `first`, and the base config carried `after` — both rejected the whole save at the host. The builder, all 60 active templates and the conflict checker now use the live spelling, with before-torrents mapped to the widest candidate pool. The Fine-Tune attempt count finally lands in maxAttempts instead of a key upstream never read, which closes the v3.0 known gap, and the template validator now rejects out-of-enum failover positions so this class cannot return.
  </Card>
  <Card title="Import-link URLs are HTML-escaped" icon="gauge">
    six result panels rendered the paste-service URL into the page unescaped. A hostile paste response could have injected markup; every one now goes through the same escaper the rest of the app uses. No known exploit, found and fixed in a hardening pass that also confirmed share links still carry settings only, stored snapshots still scrub credentials, and display names are still sanitised at every write path.
  </Card>
</CardGroup>

## Configurator v3.11 (Sep 25 2026)

<CardGroup cols={2}>
  <Card title="Configs rejected on import" icon="sparkles">
    fixed. Vidhin05 removed the HHWEB release group from two ranked patterns, Radarr Web T3 and Sonarr Web T3, and every Core Builds surface still carried the old string. Hosts check regex by exact string equality against their allowlist, so two of the 91 patterns in a generated config no longer matched and the whole config was refused — which looks like the addons simply not being configured. Nothing shipped on our side to cause it and nothing had to: the allowlist moved underneath us. Both patterns are re-derived verbatim from upstream across the configurator, the CLI, the shared filter files and 43 templates, each of which bumps so the update banner offers the corrected version. Audited the whole fleet against the live allowlist rather than only the reported case: these two were the only mismatches.
  </Card>
  <Card title="The drift watcher that should have caught this" icon="bolt">
    it ran every night and reported success while the snapshot sat stale. It piped the check into tee and then read $?, which is tee's status and always zero, so the step that opens a drift issue never ran. Worse, the 'back in sync' branch is the one that did run, and it closes an open drift issue — so a real report would have been retracted automatically. It now reads the checker's own status, and it no longer treats an unreachable upstream as proof of sync.
  </Card>
  <Card title="Debridio add-ons no longer export an invalid config" icon="shield-check">
    Debridio TMDB, TVDB and Watchtower were offered as simple on/off toggles, but each requires an API key that has no default, so switching one on produced a config the host refused. They were classified as safe by a generated options map that is missing 11 required options across 8 presets, and the test guarding that classification read the same map, so it agreed. The three now carry their key, and the check reads the live host contract instead of the map it is meant to be checking.
  </Card>
</CardGroup>

## Configurator v3.10 (Sep 19 2026)

<CardGroup cols={2}>
  <Card title="Stream statistics off by default" icon="sparkles">
    the Removal Reasons, Included Reasons and Pipeline Timing cards no longer appear among your streams. They are AIOStreams statistics output and Core Builds was asking for them: the Stable profile set statistics.enabled with addon, filter and timing stats. It was the only profile doing so, and 66 of the 69 checked-in templates already shipped them off, so the two Core Stable templates were the outliers. On Android TV the cards render above the streams, which made diagnostics the first thing on screen. hideErrors stays off, which is what actually keeps real failures visible. The Stable templates go to 1.0.1 so the update banner offers the change to anyone already running them.
  </Card>
  <Card title="Banner Studio contrast and clamp fixes" icon="bolt">
    every brand now carries its own background, and an unset background picks it up rather than falling back to one shared colour. All 18 brands clear the 2.25:1 contrast floor on their own default; Disney+ was 1.98:1 and could not be fixed from the UI at all, and is now 5.83:1. The clear-space clamp reports proportionally, so the roughly 1px trim at the shipped default stops warning while a genuine 72px clamp still does, and a failing contrast check now offers a one-tap remedy instead of a bare button. The tool also gained its first tests — 69 of them, plus 15 for the Badge Builder that had never run on a pull request.
  </Card>
  <Card title="What's New card titles" icon="shield-check">
    the docs site builds each release card by splitting a changelog item on its first em dash, so items written as one long sentence shipped cards with 300-character titles, or with the same paragraph printed as both title and body. Two of each went out with v3.9. The renderer now derives a short title when an item lacks one, and a blocking check refuses a malformed item in the release being cut.
  </Card>
</CardGroup>

## Configurator v3.9 (Sep 17 2026)

<CardGroup cols={2}>
  <Card title="Optional scrapers in Advanced extras" icon="sparkles">
    four more can be switched on: NekoBT, Sootio, WebStreamr and YaStream — and the cards now say when a route cannot use them. Three of the four are already advertised disabled on some routes, so the toggle flips that existing entry rather than emitting a second one with a duplicate instanceId. The routes differ and the UI no longer hides that: Usenet builds its own addon list and takes none of the four, HTTP takes two, and AIOStreams refuses Sootio on any route with no service behind it. A card the current route cannot satisfy is greyed out with the reason instead of accepting the click, staying ticked, and exporting a config without the preset — which is indistinguishable from it having worked. With every toggle off, the generated template is byte-identical to before.
  </Card>
  <Card title="Landing page rebuilt" icon="bolt">
    a Lean / Standard / Maximum preset row on a first visit, a wall showing the real stream cards each formatter draws rather than describing them, and copy that says the install can write the whole stack into your Stremio account. Spacing, colour and type now come from one token set across all seven stylesheets, and the layout collapses to two bands on a phone. A test pins the small-text count so microcopy cannot keep shrinking — the 17px phone root scales it.
  </Card>
  <Card title="Shared export pre-flight" icon="shield-check">
    export now runs the same check as install. It used to check exactly one thing — that a service was picked — while install ran the full check, even though both produce the same config. A template with no API key, or one over the payload limit, downloaded cleanly and only failed later inside AIOStreams. Both paths now share one policy and show the same findings, with export naming any credential fields the downloaded file carries.
  </Card>
  <Card title="Midnight's host version corrected" icon="sliders">
    it was recorded as running AIOStreams 2.33.2 when it had moved to 2.34.0. The host registry decides what each instance may receive, so configs using 2.34 features were being routed away from it and the picker advertised the wrong version. Re-checked every host against its own status endpoint.
  </Card>
  <Card title="Single-title buffering guide" icon="gauge">
    troubleshooting has a decision tree for the case where one title buffers forever and everything else plays. That shape is not a config fault: Real-Debrid removes files by filename keyword, so every candidate for that one title returns 404 for Real-Debrid users while other services play it normally.
  </Card>
</CardGroup>
