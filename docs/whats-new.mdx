# What's New in the Configurator

This page is regenerated from `configurator/src/data/changelog.js` by `scripts/sync-docs.py`, so it always reflects the latest shipped configurator version (currently **v3.16**).

For the template-suite release log, see the [Changelog](https://corebuilds-docs.docsalot.dev/changelog).

## Configurator v3.16 (Oct 3 2026)

<CardGroup cols={2}>
  <Card title="Builds save again: subtitles now default to OpenSubtitles v3+" icon="sparkles">
    AIOSubtitle, the subtitle source every build used by default, now takes about 12 seconds to answer. AIOStreams loads every add-on before it saves, so hosts refused the whole save with 'Failed to fetch manifest for AIOSubtitle: 502 - Bad Gateway'. New builds use OpenSubtitles v3+, which answers in under a second, and saved sessions still on the old default move over automatically. AIOSubtitle stays available, labelled as slow.
  </Card>
  <Card title="SubDL without a key no longer blocks the save" icon="bolt">
    AIOStreams requires a SubDL API key, but the configurator included SubDL even when the key field was empty, and the save was refused. SubDL is now only added once a key is entered; until then the build uses OpenSubtitles v3+, so it always has subtitles.
  </Card>
</CardGroup>

## Configurator v3.15 (Oct 3 2026)

<CardGroup cols={2}>
  <Card title="Built against AIOStreams 2.35.7" icon="sparkles">
    the configurator’s schema was still read from AIOStreams 2.34.1, while every public host had moved to 2.35.4 or later. It is now read from the 2.35.7 release, which is also the new default compatibility target. Upstream only added things between the two (two new add-ons, five new settings), so no setting the configurator writes changed meaning. 2.35.4 and 2.35.5, which Wizaardd, ATBP and Omni’s run, have the same schema as 2.35.7.
  </Card>
  <Card title="Generated configs now say they target 2.35.7" icon="bolt">
    besides the usual version stamp (coreBuildsVersion 3.14 to 3.15), the only change in generated output is the compatibility-target stamp in the template metadata (coreBuildsAIOStreamsTarget), which moves from 2.34.1 to 2.35.7. Filters, sorting, scrapers and formatting are byte-for-byte the same, so re-importing changes nothing AIOStreams acts on. Saved sessions that picked a target keep it.
  </Card>
  <Card title="Names and settings from links can no longer inject page markup" icon="shield-check">
    a template name, a custom formatter label, an unrecognised setting from a shared link or imported config, and entries in the local backup history were written into the page as HTML. A crafted link could have run script in the configurator. They are now escaped wherever they are shown, and help tooltips keep their text out of the page attributes. Found by CodeQL; all 11 of its 'DOM text reinterpreted as HTML' alerts are fixed.
  </Card>
  <Card title="Upstream watch re-pinned" icon="sliders">
    the AIOStreams contract watcher had flagged additive drift since September 26 (#770). It is re-pinned, and its source extraction no longer depends on GitHub’s API, which some networks refuse.
  </Card>
</CardGroup>

## Configurator v3.14 (Oct 2 2026)

<CardGroup cols={2}>
  <Card title="Default builds get their scrapers back" icon="sparkles">
    the Balanced profile, which every standard build has used since August, kept only a fixed short list of sources: a TorBox build shipped three torrent scrapers (StremThru Torz, Meteor, Comet) where an Advanced build ships eight. AIOStreams applies a template by replacing the whole addon list, so every update also deleted MediaFusion, EZTV, Torrent Galaxy, Zilean and Knaben from configs that had them. All five are back in Balanced; on P2P and EasyNews-only builds the four that need a debrid service are left out (see below). Simple Mode and Quick Install keep the short Stable list on purpose. The Knaben and Zilean toggle cards are gone: every build with a torrent debrid service already includes both, and neither can run without one, so the cards could not change anything.
  </Card>
  <Card title="Default builds get their release filtering back" icon="bolt">
    Balanced was meant to drop remote scoring and instead deleted every regex list, including the inline ones copied verbatim from host allowlists. Default users lost release-group ranking and the exclusions for upscaled, BR-DISK, extras and retagged releases, while the sort order kept a regexScore step that had nothing left to score. The inline lists return; synced regex URLs stay off, so nothing new depends on a remote file or a host allowlisting a URL.
  </Card>
  <Card title="P2P and EasyNews-only builds save again" icon="shield-check">
    EZTV, Torrent Galaxy, Knaben and Zilean are AIOStreams built-ins that need a torrent debrid service, and AIOStreams validates a config by building every enabled addon: one of them with no such service refuses the whole save, not just that addon. Advanced builds without debrid shipped all four switched on. They are now left out of builds with no debrid service and stay in everywhere else, so the save succeeds; rebuild after adding a debrid service to get them.
  </Card>
  <Card title="4K builds rank cached results first again" icon="sliders">
    4K builds sort every 2160p above every 1080p, but the same step also put quality above cache status, so an uncached 4K REMUX outranked a cached 4K WEB-DL. On a debrid account the top result could start a download instead of playing — the likely cause of reports that sorting sometimes misbehaves. Cached now comes straight after resolution in every 4K sort list, including Simple Mode and Quick Install builds: 4K still beats 1080p, and inside each resolution cached beats uncached. 1080p series also gain the separate cached/uncached ordering movies and anime always had, so uncached episodes now rank by seeders the way uncached movies do.
  </Card>
  <Card title="Sort steps that do nothing are removed" icon="gauge">
    regexScore is now dropped whenever a config carries no ranked regex, and audioChannel is dropped from generated configs because AIOStreams has no sorter case for it: it compares every stream as equal. It returns once upstream handles it. Checked-in templates keep it unchanged.
  </Card>
  <Card title="Offline mode retired, and the stale cache it could leave" icon="wand">
    the configurator registered a service worker that served the whole app from cache without ever checking for updates, under a cache name unchanged since v3.10. It never ran on the main configurator page, but it did install for anyone who opened the copy under /configurator/dist/, and those browsers kept running the v3.10 build. The page no longer registers one, removes any it finds, and the worker file is replaced by one that clears its cache, unregisters itself and reloads onto the current build.
  </Card>
  <Card title="Offcloud, PikPak and Seedr builds save again" icon="layers">
    the configurator asked each for a single API key, but AIOStreams requires Offcloud's API key plus account email and password, PikPak's email and password, and a Seedr encoded token issued by MediaFusion; a direct install with any of them was refused. The forms now ask for exactly those fields. Seedr builds also stop adding StremThru, which cannot use Seedr and failed the save on its own: MediaFusion is the one AIOStreams source that supports it.
  </Card>
  <Card title="EasyNews, Usenet, Seedr and Debridio builds save again" icon="bug">
    every one of these was refused by AIOStreams, and it is already the case on the live site. Found by saving 462 generated configs into a real AIOStreams 2.35.7: SeaDex, like EZTV and Knaben, only runs with a torrent debrid service but was added to every build except P2P; EasyNews Search on the Usenet route asked for an AIOStreams Auth setting unless told to use only EasyNews; and Debridio, NekoBT, Jackett, Prowlarr, Jackettio and the Newznab indexers were emitted on builds with no service able to back them. Each is now added only when something can run it, the EasyNews add-on cards ask for EasyNews as a service first, and the debrid-only cards are greyed out on builds without a torrent debrid service.
  </Card>
  <Card title="Retired add-ons can no longer break a save" icon="sparkles">
    TorBox (addon), USA TV and Debridio Watchtower were offered as toggles, but AIOStreams marks all three removed and refuses any config containing one, on every host. They are gone from the list and stripped from older saved setups. Bitmagnet stays, but only works on hosts that configure it, so it is now stripped on ElfHosted, ATBP, Omni's and Wizaardd; the live host check also reads each host's own disabled-add-on list, which is how it now catches Viren's nightly blocking Torrentio.
  </Card>
  <Card title="Anime builds get an anime scraper on the default profile" icon="bolt">
    choosing Anime or Movies + Anime added AnimeTosho only on Advanced; the default Balanced profile stripped it, so the choice changed nothing. It now ships on both whenever a torrent debrid service is set. Like EZTV and Knaben, AnimeTosho cannot run without one, and an Advanced anime build on P2P or EasyNews carried it anyway, which refused the save; those builds now leave it out.
  </Card>
  <Card title="Age Rating Limit removed" icon="shield-check">
    the filter wrote a certification() rule, but AIOStreams has no such function: on Advanced and Labs the host refused the whole config, and on Stable and Balanced the rule was silently dropped, so the control did nothing while saying it filtered. The control is gone until AIOStreams ships a rating filter; saved setups that chose a rating keep loading.
  </Card>
  <Card title="Descriptions checked against AIOStreams and the live hosts" icon="sliders">
    every host now shows the version it actually runs (2.35.4 to 2.35.7; the picker still said 2.34.1, and Omni's is no longer behind, so it drops 'legacy'). The Recommended Stack panel is rewritten: it called StremThru Torz and Knaben usenet sources, recommended Torrentio, and listed developer notes. Also corrected: Brazuca Torrents is P2P, not debrid (and is now selectable on P2P builds); EasyDebrid is a debrid service, not an aggregator; Samsung TVs gained AV1 in 2020; the Fire TV Stick HD plays HDR10 and HLG; the Anime option keeps dual-audio releases rather than filtering to SeaDex only; the troubleshooter quoted 8 excluded and 107 ranked patterns where Balanced ships 3 and about 80; and Stream Pool showed two contradictory sets of counts and now shows the stop count the build uses, saying plainly that Stable and Balanced ignore it.
  </Card>
  <Card title="Updating keeps your setup" icon="gauge">
    applying a template update rebuilt every source from defaults, so scrapers you had added, custom endpoints, per-instance keys and timeouts disappeared, and sections you chose to keep were overwritten. Updates now merge into what you have: imported sources, IDs, endpoints, credentials and timeouts are kept, declined changes stay declined, and the preview compares the actual output you would install. Preview and Cancel change nothing, Undo restores the previous setup, and the update screen says plainly that confirming here does not change an addon already installed in AIOStreams until you reinstall. A saved NZBHydra, Jackett or Prowlarr key is reused only when the imported preset points at the same address, so a key is never sent to an indexer it was not entered for.
  </Card>
  <Card title="First-time Nuvio setup" icon="wand">
    the Nuvio route now builds through the same pipeline as every other install, honours the host you picked instead of swapping in another one, separates import links from manifests, and offers the JSON as a download if every paste service fails. Public import links strip access keys and private URLs and disable any source that needed them.
  </Card>
  <Card title="Release notes now say when generated output is unchanged" icon="layers">
    3.12 to 3.13 produced byte-identical configs, and default-profile users saw none of 3.9 through 3.11 either, yet each release read as a config change: re-importing showed no changes in AIOStreams and looked broken. A new check blocks any release that changes no generated config unless its notes say so, and blocks the opposite claim when output did change.
  </Card>
</CardGroup>

## Configurator v3.13 (Sep 27 2026)

<CardGroup cols={2}>
  <Card title="Configuration Doctor repairs hardened" icon="sparkles">
    three fixes from the post-release audit of the new Doctor. Credential redaction now covers the whole imported file: the diagnosis recorded paths relative to the unwrapped template while the repair pass walked the wrapper, so on array-wrapped exports every selected redaction silently did nothing and the 'repaired' download still carried the keys. The scan now walks the entire input — wrapper keys, string arrays (a token in a synced-URL entry is flagged like any other), and every config in a multi-template array, not just the first one the structural checks unwrap. Removing a dead preset now also removes its instanceId from groups — AIOStreams rejects a config whose group references a preset that no longer exists, which would have turned a safe repair into a save failure; a grouping left empty is dropped, and groups disable entirely when none remain.
  </Card>
  <Card title="Install verification is now real" icon="bolt">
    the Full Stack success panel said your addons 'were read back from your account', but nothing read them back. The install now ends with an actual re-read of the Stremio addon collection, checked against what was requested; a missing addon is reported plainly instead of celebrated. The Doctor's payload gauge also now measures the config the host actually receives rather than the template wrapper around it, so a wrapped export is no longer counted against the 100 KB save limit twice over.
  </Card>
</CardGroup>
