## Configurator v3.8 (Sep 11 2026)

<CardGroup cols={2}>
  <Card title="Self-hosted instances can be updated in place instead of accumulating configs. The UUID field was hidden whenever the host was set to Custom / Self-hosted, so every Get Install Link posted a new configuration and orphaned the previous one" icon="sparkles">

Known gap: an instance running with AIOSTREAMS_AUTH_REQUIRED still has nowhere to enter its access key, so those saves are refused by the host regardless of this change.

  <Card title="The exported JSON contains your API keys in plain text, and now says so at the moment you download it. Export has never stripped credentials" icon="bolt">
    the sanitiser that clears them runs on share links and imports only — so the downloaded file carries whatever you entered, and these files get posted publicly when people ask for help. The notice names which fields are embedded, never their values, and points at Copy a safe feedback report instead; it stays silent when nothing is set. A test asserting that 'exports never carry credentials' was passing only because that case entered none, and now pins both directions.
  </Card>
  <Card title="A hand-typed manifest password is checked before it is sent. Anything shorter than 8 characters was accepted, posted, and bounced by the host as 'Invalid addon password', a message that never says what is wrong; the reason is now shown inline while it can still be fixed. This is a Core Builds floor rather than a value read from AIOStreams" icon="shield-check">
    the pinned schema carries no password rule, so the host's own requirement is still unknown. Auto-generate is unaffected and continues to produce 12 characters or more.
  </Card>
  <Card title="The CORS proxy stopped serving the previous build's statistics payload after a deploy. The public /api/stats response was cached under a path-only key, so a deploy that narrowed the payload kept answering from the old build's cached body for up to 60 seconds" icon="sliders">
    the same window that failed the post-deploy smoke gate. The cache key now carries the worker version, so a new build is always a new key.
  </Card>
  <Card title="Operator tooling for the proxy: the full statistics view and detailed health sit behind an ADMIN_TOKEN, with a token-sync workflow, an OPERATOR.md runbook and an operator-stats.sh helper, and wrangler secret put is pinned to --env on production so a secret cannot land on the wrong environment." icon="gauge">
    Operator tooling for the proxy: the full statistics view and detailed health sit behind an ADMIN_TOKEN, with a token-sync workflow, an OPERATOR.md runbook and an operator-stats.sh helper, and wrangler secret put is pinned to --env on production so a secret cannot land on the wrong environment.

## Configurator v3.0 (Sep 1 2026)

<CardGroup cols={2}>

  <Card title="1440p was being ranked below 720p in every 4K build" icon="sliders">
    the 4K preference list named 2160p, 1080p, 720p and Unknown but omitted 1440p, and AIOStreams scores an unlisted resolution as negative infinity. Any 1440p file therefore sorted beneath everything else instead of just under 4K. It is now listed in its proper place. If you use a 1440p display or grab 1440p releases to save bandwidth, this is the fix you noticed was missing.
  </Card>
  <Card title="Options your instance will not accept are now disabled before you pick them, with the reason on the option" icon="gauge">
    on the ElfHosted community instance that means Torrentio, AnimeKitsu, Torrent Catalogs, P2P and HTTP appear greyed out and unselectable rather than being silently dropped later. Core Builds checks the host you selected, falls back to a stored capability list when the browser cannot reach it, and applies the same check to the exported JSON and the direct install, so neither can carry something the target host rejects. A Host Compatibility panel lists what was blocked, what was removed from your export, and anything kept that might still be refused.
  </Card>
  <Card title="Restricted hosts strip custom regex, and now you are told so" icon="wand">
    ElfHosted runs with regex filtering limited to a published allowlist, and sending a pattern outside it makes the instance reject the entire save, not just that rule. Core Builds removes unlisted patterns before export and names each one. Synced regex sources are a separate allowlist and are treated separately: the Vidhin ranked-regex feed is on ElfHosted's allowed list, so it stays. On a host we cannot verify, nothing is removed and the panel flags what may be refused instead.
  </Card>
  <Card title="The generated config is now built from a specific AIOStreams release rather than a moving target" icon="layers">
    pinned to v2.33.2 and regenerated by a script that proves the commit is the one that release tag points at. Six settings Core Builds had been emitting for a while turned out not to exist in AIOStreams at all and were being discarded on arrival: maxResults, maxResultsPerResolution, seadexBestOnly, excludedStreamSources, enhanceResults and minSeeders. They are gone from the output. excludedStreamSources is replaced by excludedStreamTypes, which the instance does read.
