## Configurator v3.31 (Oct 31 2026)

<CardGroup cols={2}>
  <Card title="One Core Builds template inside AIOStreams" icon="sparkles">
    a single template asks what you watch on (26 devices), the picture you want, what matters most, whether to show only streams that play straight away, your language and whether you mostly watch anime, then uses the service you pick in AIOStreams (none gives the free P2P setup). It builds the same config Quick install would for those answers. It is first in the template directory, with Import buttons for every host.
  </Card>
  <Card title="Proven against AIOStreams itself" icon="bolt">
    a test runs the template through AIOStreams’ own template code, fetched at the pinned release, for every answer and service, and fails on any difference from the configurator’s output; a browser test checks that output against what Quick install builds for every service and device. Picking two services at once gives one config with both, and those combinations are saved in a real AIOStreams on every pull request.
  </Card>
  <Card title="Smaller operator collection" icon="shield-check">
    the collection hosts add to TEMPLATE_URLS now holds just this template (94 KB instead of 3.4 MB) and no longer includes personal templates. It still carries every regex pattern and synced address the other templates use, so instances that trusted them keep trusting them.
  </Card>
  <Card title="Generated output unchanged" icon="sliders">
    every config the configurator and the CLI build is byte-for-byte what 3.30 produced apart from the version stamp; the new template is a separate file that reproduces that output.
  </Card>
</CardGroup>

## Configurator v3.30 (Oct 30 2026)

<CardGroup cols={2}>
  <Card title="Update my setup" icon="sparkles">
    once Core Builds has saved a config to your AIOStreams and this browser still has its UUID and password, the first screen offers Update my setup. Streams use the update straight away; changed catalogs show after reinstalling from your manifest link.

Your password goes to a host from the list or your own custom address, passing through the Core Builds relay, which forwards it and keeps nothing.
  </Card>
  <Card title="Generated output unchanged" icon="shield-check">
    every config the configurator and the CLI build is byte-for-byte what 3.29 produced apart from the version stamp; only the way an existing setup is updated changed.
  </Card>
</CardGroup>
