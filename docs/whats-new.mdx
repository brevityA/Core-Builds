## Configurator v3.9 (Sep 17 2026)

<CardGroup cols={2}>
  <Card title="Optional scrapers in Advanced extras" icon="sparkles">
    four more can be switched on: NekoBT, Sootio, WebStreamr and YaStream — and the cards now say when a route cannot use them. Three of the four are already advertised disabled on some routes, so the toggle flips that existing entry rather than emitting a second one with a duplicate instanceId. The routes differ and the UI no longer hides that: Usenet builds its own addon list and takes none of the four, HTTP takes two, and AIOStreams refuses Sootio on any route with no service behind it. A card the current route cannot satisfy is greyed out with the reason instead of accepting the click, staying ticked, and exporting a config without the preset — which is indistinguishable from it having worked. With every toggle off, the generated template is byte-identical to before.
  </Card>

    a Lean / Standard / Maximum preset row on a first visit, a wall showing the real stream cards each formatter draws rather than describing them, and copy that says the install can write the whole stack into your Stremio account. Spacing, colour and type now come from one token set across all seven stylesheets, and the layout collapses to two bands on a phone. A test pins the small-text count so microcopy cannot keep shrinking — the 17px phone root scales it.
  </Card>
  <Card title="Shared export pre-flight" icon="shield-check">
    export now runs the same check as install. It used to check exactly one thing — that a service was picked — while install ran the full check, even though both produce the same config. A template with no API key, or one over the payload limit, downloaded cleanly and only failed later inside AIOStreams. Both paths now share one policy and show the same findings, with export naming any credential fields the downloaded file carries.
  </Card>
  <Card title="Midnight's host version corrected" icon="sliders">
    it was recorded as running AIOStreams 2.33.2 when it had moved to 2.34.0. The host registry decides what each instance may receive, so configs using 2.34 features were being routed away from it and the picker advertised the wrong version. Re-checked every host against its own status endpoint.
  </Card>
  <Card title="Single-title buffering guide" icon="gauge">
    troubleshooting has a decision tree for the case where one title buffers forever and everything else plays. That shape is not a config fault: Real-Debrid removes files by filename keyword, so every candidate for that one title returns 404 for Real-Debrid users while other services play it normally.

## Configurator v3.8 (Sep 17 2026)

<CardGroup cols={2}>
  <Card title="Self-hosted instances can be updated in place…" icon="sparkles">
    Self-hosted instances can be updated in place instead of accumulating configs. The UUID field was hidden whenever the host was set to Custom / Self-hosted, so every Get Install Link posted a new configuration and orphaned the previous one — the public hosts have always offered that field. It is now shown for any single host, self-hosted included, and the CORS proxy's custom lane accepts PATCH /api/v1/user/<id> using the same bounded id shape the allowlisted lane already used. Leave it blank to create a new config exactly as before. Known gap: an instance running with AIOSTREAMS_AUTH_REQUIRED still has nowhere to enter its access key, so those saves are refused by the host regardless of this change.
  </Card>
  <Card title="This also changes what a UUID does on the public…" icon="bolt">
    This also changes what a UUID does on the public hosts, and not only on self-hosted ones. Entering a UUID together with a password used to return a link to the configuration you already had, silently discarding the template you had just built; that combination now updates that configuration in place, which is what the Auto host has always done. A UUID with no password still only rebuilds the link, and a blank UUID still creates a new configuration — so the way to keep a second config is to leave the field empty.
  </Card>
  <Card title="The exported JSON contains your API keys in…" icon="shield-check">
    The exported JSON contains your API keys in plain text, and now says so at the moment you download it. Export has never stripped credentials — the sanitiser that clears them runs on share links and imports only — so the downloaded file carries whatever you entered, and these files get posted publicly when people ask for help. The notice names which fields are embedded, never their values, and points at Copy a safe feedback report instead; it stays silent when nothing is set. A test asserting that 'exports never carry credentials' was passing only because that case entered none, and now pins both directions.
  </Card>
  <Card title="A hand-typed manifest password is checked before…" icon="sliders">
    A hand-typed manifest password is checked before it is sent. Anything shorter than 8 characters was accepted, posted, and bounced by the host as 'Invalid addon password', a message that never says what is wrong; the reason is now shown inline while it can still be fixed. This is a Core Builds floor rather than a value read from AIOStreams — the pinned schema carries no password rule, so the host's own requirement is still unknown. Auto-generate is unaffected and continues to produce 12 characters or more.
  </Card>
  <Card title="The CORS proxy stopped serving the previous…" icon="gauge">
    The CORS proxy stopped serving the previous build's statistics payload after a deploy. The public /api/stats response was cached under a path-only key, so a deploy that narrowed the payload kept answering from the old build's cached body for up to 60 seconds — the same window that failed the post-deploy smoke gate. The cache key now carries the worker version, so a new build is always a new key.
  </Card>
  <Card title="Operator tooling for the proxy: the full…" icon="wand">
    Operator tooling for the proxy: the full statistics view and detailed health sit behind an ADMIN_TOKEN, with a token-sync workflow, an OPERATOR.md runbook and an operator-stats.sh helper, and wrangler secret put is pinned to --env on production so a secret cannot land on the wrong environment.
  </Card>
</CardGroup>

## Configurator v3.7 (Sep 6 2026)

<CardGroup cols={2}>
  <Card title="Version honesty: the badge, package.json and the…" icon="sparkles">
    Version honesty: the badge, package.json and the template stamp now all report this release (they disagreed — badge v3.1, package 3.1.0, tag v3.7.0) and a test fails if they ever drift apart again. The default AIOStreams compatibility target moves from the stale 2.32.0 to the pinned 2.34.0, with 2.33.2 and 2.34.0 added to the target list so it covers every version the live fleet actually runs.
  </Card>
  <Card title="Fixed: EasyNews-only Direct Install no longer…" icon="bolt">
    Fixed: EasyNews-only Direct Install no longer fails with 'Library requires at least one usable service'. AIOStreams builds the Library addon from your services, and EasyNews cannot back it — the library preset is now omitted whenever no library-capable (debrid) service is enabled, on every route, and EasyNews configs install clean. EasyNews plus any debrid keeps the library.
  </Card>
  <Card title="Direct Install now refuses to post without the…" icon="shield-check">
    Direct Install now refuses to post without the keys the host demands, naming exactly what is missing ('Option apiKey is required' was the previous failure, delivered by the host after the fact). Correction (v3.8): this entry originally ended 'Export JSON remains keyless by design', which was never true — export has always embedded whatever credentials you entered, and the sanitiser that strips them runs on share links and imports only. Treat an exported file as secret; see the v3.8 note above.
  </Card>
  <Card title="The host picker now states each host's…" icon="sliders">
    The host picker now states each host's capabilities and its AIOStreams version before you deploy — ElfHosted says 'Debrid only — no P2P/HTTP', and the three hosts still on 2.33.2 say so. A config using features newer than a host is not routed there, and a P2P config can no longer be sent to ElfHosted.
  </Card>
  <Card title="The landing is Express-first: one primary card…" icon="gauge">
    The landing is Express-first: one primary card for the five-step install (service → device → resolution → key → Deploy), with Advanced Builder, Update Existing and the Setup Genie demoted to plain links. The Genie page itself is unchanged.
  </Card>
</CardGroup>
