# What's New in the Configurator

This page is regenerated from `configurator/src/data/changelog.js` by `scripts/sync-docs.py`, so it always reflects the latest shipped configurator version (currently **v3.14**).

For the template-suite release log, see the [Changelog](https://corebuilds-docs.docsalot.dev/changelog).

## Configurator v3.14 (Oct 2 2026)

<CardGroup cols={2}>
  <Card title="Default builds get their scrapers back" icon="sparkles">
    the Balanced profile, which every standard build has used since August, kept only a fixed short list of sources: a TorBox build shipped three torrent scrapers (StremThru Torz, Meteor, Comet) where an Advanced build ships eight. AIOStreams applies a template by replacing the whole addon list, so every update also deleted MediaFusion, EZTV, Torrent Galaxy, Zilean and Knaben from configs that had them. All five are back in Balanced; on P2P and EasyNews-only builds the four that need a debrid service are left out (see below). Simple Mode and Quick Install keep the short Stable list on purpose. Switching on the optional Knaben card no longer adds a second copy of a source every build already includes.
  </Card>
  <Card title="Default builds get their release filtering back" icon="bolt">
    Balanced was meant to drop remote scoring and instead deleted every regex list, including the inline ones copied verbatim from host allowlists. Default users lost release-group ranking and the exclusions for upscaled, BR-DISK, extras and retagged releases, while the sort order kept a regexScore step that had nothing left to score. The inline lists return; synced regex URLs stay off, so nothing new depends on a remote file or a host allowlisting a URL.
  </Card>
  <Card title="P2P and EasyNews-only builds save again" icon="shield-check">
    EZTV, Torrent Galaxy, Knaben and Zilean are AIOStreams built-ins that need a torrent debrid service, and AIOStreams validates a config by building every enabled addon: one of them with no such service refuses the whole save, not just that addon. Advanced builds without debrid shipped all four switched on. They are now left out of builds with no debrid service and stay in everywhere else, so the save succeeds; rebuild after adding a debrid service to get them.
  </Card>
  <Card title="4K builds rank cached results first again" icon="sliders">
    4K builds sort every 2160p above every 1080p, but the same step also put quality above cache status, so an uncached 4K REMUX outranked a cached 4K WEB-DL. On a debrid account the top result could start a download instead of playing — the likely cause of reports that sorting sometimes misbehaves. Cached now comes straight after resolution in every 4K sort list, including Simple Mode and Quick Install builds: 4K still beats 1080p, and inside each resolution cached beats uncached. 1080p series also gain the separate cached/uncached ordering movies and anime always had, so uncached episodes now rank by seeders the way uncached movies do.
  </Card>
  <Card title="Sort steps that do nothing are removed" icon="gauge">
    regexScore is now dropped whenever a config carries no ranked regex, and audioChannel is dropped from generated configs because AIOStreams has no sorter case for it: it compares every stream as equal. It returns once upstream handles it. Checked-in templates keep it unchanged.
  </Card>
  <Card title="Offline mode retired, and the stale cache it could leave" icon="wand">
    the configurator registered a service worker that served the whole app from cache without ever checking for updates, under a cache name unchanged since v3.10. It never ran on the main configurator page, but it did install for anyone who opened the copy under /configurator/dist/, and those browsers kept running the v3.10 build. The page no longer registers one, removes any it finds, and the worker file is replaced by one that clears its cache, unregisters itself and reloads onto the current build.
  </Card>
  <Card title="Release notes now say when generated output is unchanged" icon="layers">
    3.12 to 3.13 produced byte-identical configs, and default-profile users saw none of 3.9 through 3.11 either, yet each release read as a config change: re-importing showed no changes in AIOStreams and looked broken. A new check blocks any release that changes no generated config unless its notes say so, and blocks the opposite claim when output did change.
  </Card>
</CardGroup>

## Configurator v3.13 (Sep 27 2026)

<CardGroup cols={2}>
  <Card title="Configuration Doctor repairs hardened" icon="sparkles">
    three fixes from the post-release audit of the new Doctor. Credential redaction now covers the whole imported file: the diagnosis recorded paths relative to the unwrapped template while the repair pass walked the wrapper, so on array-wrapped exports every selected redaction silently did nothing and the 'repaired' download still carried the keys. The scan now walks the entire input — wrapper keys, string arrays (a token in a synced-URL entry is flagged like any other), and every config in a multi-template array, not just the first one the structural checks unwrap. Removing a dead preset now also removes its instanceId from groups — AIOStreams rejects a config whose group references a preset that no longer exists, which would have turned a safe repair into a save failure; a grouping left empty is dropped, and groups disable entirely when none remain.
  </Card>
  <Card title="Install verification is now real" icon="bolt">
    the Full Stack success panel said your addons 'were read back from your account', but nothing read them back. The install now ends with an actual re-read of the Stremio addon collection, checked against what was requested; a missing addon is reported plainly instead of celebrated. The Doctor's payload gauge also now measures the config the host actually receives rather than the template wrapper around it, so a wrapped export is no longer counted against the 100 KB save limit twice over.
  </Card>
</CardGroup>

## Configurator v3.12 (Sep 26 2026)

<CardGroup cols={2}>
  <Card title="Fleet re-audit" icon="sparkles">
    every public host re-checked against its own status endpoint. Seven of the eight run AIOStreams 2.34.1 (six on the stable build, Viren's on its nightly); Omni's is the only 2.33.2 holdout, over six weeks behind. The schema pin, the default compatibility target and the host registry all move to 2.34.1 together, and the 2.34.1 contract was verified byte-identical to 2.34.0 in every generated file, so nothing you generate changes shape. Two corrections fell out of the audit: ATBP and Wizaardd both report regexAccess `all`, not `trusted`, so their offline defaults now say so — the live probe still wins whenever it can reach the host.
  </Card>
  <Card title="Dead settings stop being emitted, not just stripped" icon="bolt">
    v3.0 found six settings Core Builds emitted that AIOStreams never defined (maxResults, maxResultsPerResolution, seadexBestOnly, excludedStreamSources, enhanceResults, minSeeders) and began removing them at the export gate. The generators kept writing them anyway, relying on the gate to clean up. They no longer write them at all, and the native-filters policy that wrote the dead `excludedStreamSources` now writes the live `excludedStreamTypes` instead — Stable and Balanced output newly, actually excludes YouTube-type streams rather than carrying a key the host ignored. The 55 checked-in templates that carried the dead keys are cleaned (about 8 KB of payload that was stripped on every save), and the guides that described the dead keys as working now describe what the host really reads.
  </Card>
  <Card title="TorBox Search preset is allowlisted, not dead" icon="shield-check">
    the Apex, Hybrid and several Personal and Device templates ship an enabled preset pointed at TorBox's Search API, and the validator called that endpoint shut down. It is not down; TorBox restricts it to allowlisted caller hosts, so it resolves on approved managed hosts and silently times out everywhere else, which reads as slow or missing Usenet results with no error. The warning now says that and points at two new troubleshooting entries: the allowlist (with the remedy — move hosts, or swap in a personal indexer) and the separate TorBox CDN routing advisory, where some hosts need the CDN set manually for AIOStreams-installed addons.
  </Card>
  <Card title="Failover replaces NZB Failover, and two save rejections go with it" icon="sliders">
    AIOStreams renamed nzbFailover to the generic failover (Usenet plus debrid) and migrates the old spelling before validating, passing position through blindly. Core Builds emitted two positions outside the new enum: the before-torrents option wrote `first`, and the base config carried `after` — both rejected the whole save at the host. The builder, all 60 active templates and the conflict checker now use the live spelling, with before-torrents mapped to the widest candidate pool. The Fine-Tune attempt count finally lands in maxAttempts instead of a key upstream never read, which closes the v3.0 known gap, and the template validator now rejects out-of-enum failover positions so this class cannot return.
  </Card>
  <Card title="Import-link URLs are HTML-escaped" icon="gauge">
    six result panels rendered the paste-service URL into the page unescaped. A hostile paste response could have injected markup; every one now goes through the same escaper the rest of the app uses. No known exploit, found and fixed in a hardening pass that also confirmed share links still carry settings only, stored snapshots still scrub credentials, and display names are still sanitised at every write path.
  </Card>
  <Card title="Configuration Doctor in the Template Inspector" icon="wand">
    paste, drop or upload any AIOStreams config and get structured findings on top of the existing validation: removed presets, duplicate or missing instance IDs, embedded credentials, very long addon timeouts, strict-matching traps, oversized payloads and legacy expression syntax. Each finding that has a deterministic fix offers a selectable safe repair; selected repairs are previewed against a clone and downloaded as a separate file, the original is never modified, and everything runs locally in the browser — nothing is uploaded anywhere. Credential findings name the field, never the value.
  </Card>
</CardGroup>

## Configurator v3.11 (Sep 25 2026)

<CardGroup cols={2}>
  <Card title="Configs rejected on import" icon="sparkles">
    fixed. Vidhin05 removed the HHWEB release group from two ranked patterns, Radarr Web T3 and Sonarr Web T3, and every Core Builds surface still carried the old string. Hosts check regex by exact string equality against their allowlist, so two of the 91 patterns in a generated config no longer matched and the whole config was refused — which looks like the addons simply not being configured. Nothing shipped on our side to cause it and nothing had to: the allowlist moved underneath us. Both patterns are re-derived verbatim from upstream across the configurator, the CLI, the shared filter files and 43 templates, each of which bumps so the update banner offers the corrected version. Audited the whole fleet against the live allowlist rather than only the reported case: these two were the only mismatches.
  </Card>
  <Card title="The drift watcher that should have caught this" icon="bolt">
    it ran every night and reported success while the snapshot sat stale. It piped the check into tee and then read $?, which is tee's status and always zero, so the step that opens a drift issue never ran. Worse, the 'back in sync' branch is the one that did run, and it closes an open drift issue — so a real report would have been retracted automatically. It now reads the checker's own status, and it no longer treats an unreachable upstream as proof of sync.
  </Card>
  <Card title="Debridio add-ons no longer export an invalid config" icon="shield-check">
    Debridio TMDB, TVDB and Watchtower were offered as simple on/off toggles, but each requires an API key that has no default, so switching one on produced a config the host refused. They were classified as safe by a generated options map that is missing 11 required options across 8 presets, and the test guarding that classification read the same map, so it agreed. The three now carry their key, and the check reads the live host contract instead of the map it is meant to be checking.
  </Card>
</CardGroup>
