# Core Builds / AIOStreams Configurator Audit

**Audit date:** 3 August 2026 (Australia/Sydney)  
**Repository snapshot:** `41d7159` (`main`, before this patch set)  
**Scope:** GitHub Pages Configurator, shared generator/CLI, Cloudflare Worker, account tools, tests, CI, dependency hygiene, and the two reported user flows.

> **Deployment status:** the fixes in this working tree are tested locally but are **not deployed** to GitHub Pages or Cloudflare yet. The live site remains affected until this patch is committed, pushed, and the Worker is configured/deployed.

---

## Executive summary

The reports are valid and reproducible.

1. **Peerflix configs are rejected by AIOStreams.** The live configurator emits `Peerflix` without the required `options.useMultipleInstances` boolean for both P2P and HTTP templates.
2. **Nuvio import links fail because the live Cloudflare Worker has no `TEMPLATES` KV binding.** A safe invalid-JSON probe to the live `/paste` endpoint returned `HTTP 500 {"error":"KV not configured"}`. The Nuvio route also omitted the existing `dpaste.com` fallback.
3. **Public import-link uploads could expose credentials.** The former sanitizer missed `tmdbAccessToken` and `subDlApiKey`; the Nuvio special route bypassed sanitization entirely.

The patch fixes all three code paths, adds regression coverage, and strengthens CI. A Cloudflare configuration step is still required to restore the first-party paste service.

## Confirmed findings and patches

| Severity | Finding | Evidence | Patch status |
|---|---|---|---|
| **Critical – functional** | Peerflix lacks required `useMultipleInstances` | The hosted bundle contains `options:{name:"Peerflix",timeout:7e3}` in both HTTP and P2P generators. This matches the supplied AIOStreams error: `Option useMultipleInstances is required, got undefined`. | **Fixed** in `configurator/src/js/app.js` and `packages/core/src/generate-template.js`; added generator, E2E, golden, and Python-schema regression tests. |
| **Critical – availability** | Nuvio import cannot create an import URL when the Worker is unconfigured | Live safe probe: `POST /paste` with invalid JSON returns `500 KV not configured`. The Nuvio path only tried Worker then paste.rs, while the general import path also tried dpaste. | **Fixed in client** by sharing the complete Worker → paste.rs → dpaste fallback chain. **Still requires Worker KV provisioning** to restore first-party paste URLs. |
| **High – credential exposure** | Public import links could contain a TMDB Read Access Token or SubDL API key | Generated configuration uses `tmdbAccessToken` and `subDlApiKey`; the former upload code stripped only `tmdbToken`, `tmdbApiKey`, and generic `apiKey`. Nuvio uploaded its template without any sanitizer. | **Fixed** with pure `sanitizeTemplateForRemoteImport()`, used for normal and Nuvio imports. ## Changes included in this patch

### Reported flows

- Adds `useMultipleInstances: false` to every generated Peerflix preset.
- Validates Peerflix as a known preset and rejects a missing/non-boolean option in `validate_templates.py`.
- Uses one import uploader for normal and Nuvio flows:
  1. Core Builds Worker `/paste`
  2. `paste.rs`
  3. `dpaste.com`
- Sanitizes public-import payloads before any network upload.
- Shows a Nuvio reminder when a TMDB credential was stripped from the public import URL.

### Worker and deployment hardening

- Makes CORS response headers request-local.
- Documents the mandatory `TEMPLATES` KV binding in `wrangler.toml` and the Worker README.
- Updates stale Worker README instructions to current `configurator/src/js/app.js` and `npm run build` paths.

### Test/CI repairs

- Fixes account-tools and CLI `npm test` commands.
- Adds a test script for `packages/core`.
- Adds supporting-package CI for core, CLI, account tools, and Worker.
- Refreshes all configurator golden fixtures to v2.88 and includes the Peerflix schema field in P2P/HTTP fixtures.
- Adds Nuvio fallback and credential-redaction browser coverage across desktop and mobile.
- Ensures status-check tests cannot mutate repository docs.

## Required owner actions after merging

### 1. Provision and bind the Worker KV namespace

The live Worker currently cannot store templates. From `cloudflare-worker/`:

```bash
npx wrangler kv namespace create TEMPLATES
```

Copy the returned namespace ID into the uncommented binding in `wrangler.toml`:

```toml
[[kv_namespaces]]
binding = "TEMPLATES"
id = "<paste-kv-namespace-id>"
```

Then deploy:

```bash
npx wrangler deploy
```

Verify with a non-persisting invalid-JSON probe. It should return **400** (`invalid JSON`), not **500** (`KV not configured`):

```bash
curl -i -X POST 'https://core-builds-cors-proxy.tlorenzato26.workers.dev/paste' \
  -H 'Content-Type: application/json' --data 'not-json'
```

For production abuse protection, also create/bind the documented `RATELIMIT` KV namespace. Without it, the Worker intentionally degrades to allow mode and its public proxy/paste endpoints are not edge-rate-limited.

### 2. Deploy the GitHub Pages artifact

`configurator/index.html` is a tracked standalone deployment artifact and is regenerated by this patch. Push the branch to `main` (or merge a PR) so the Pages workflow publishes it. GitHub Pages may serve the previous standalone page briefly from cache; hard refresh or wait for cache expiry before testing.

### 3. Rotate potentially exposed credentials

Before this patch, public import links could include:

- TMDB Read Access Tokens (`tmdbAccessToken`)
- SubDL API keys (`subDlApiKey`)
- Any Nuvio-route TMDB credential

If such a link was shared, copied into a support post, or used during the 30-day Worker paste retention window, rotate those credentials. Standard debrid service credentials were already cleared/stripped by the old path, but rotating any credential you suspect was shared remains prudent.

## Remaining recommendations

These are not blockers for the supplied fixes, but should be scheduled.

1. **Eliminate generator duplication.** `configurator/src/js/app.js` still has a legacy preset/template assembler while the CLI uses `packages/core`. Several policy files have already drifted. Move the browser to the shared generator or add an explicit browser-vs-core parity matrix for every supported service/route.
2. **Review credential persistence.** `coreBuild` in browser `localStorage` intentionally retains provider credentials and AIOStreams/base passwords. Consider session-only storage by default, an opt-in “remember credentials” setting, and a visible “clear credentials” control.
3. **Harden CSP further.** The static page still needs `'unsafe-inline'` for scripts/styles. Moving inline bootstrapping/handlers into hashed or external assets would reduce the impact of a future DOM injection.
4. **Document the Cinebye trust boundary.** The optional Cinemeta patch sends a Stremio `authKey` to the selected Cinebye host. The UI says it uses Cinebye; make the credential hand-off explicit before enabling the action.
5. **Pin GitHub Actions to immutable commit SHAs** for stronger supply-chain protection; keep tag updates through Dependabot.
