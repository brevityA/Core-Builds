# v3.14 — intentional generation changes: 4K cached ordering, cachedSeries, P2P built-ins

Required by `tests/preflight-json-fixture.test.mjs`, which asks that every
intentional change to generated JSON be explained here.

## 1. 4K tier-first keeps `cached` directly under the tier key

`sort-policy.js#hoistResolution` used to lead every 4K scope with
`resolution > quality`, which put quality above cache status. Run through the
upstream sorter model (`tests/helpers/aiostreams-sorter-model.mjs`), an
uncached 2160p REMUX outranked a cached 2160p WEB-DL, so the top pick in a 4K
build could start a debrid download instead of playing.

New lead: the architecture's tier key, then `cached`, then the other key.

- Standard / IQR 4K: `resolution > cached > quality`
- Apex Mixed 4K: `quality > cached > resolution` (Apex Mixed has always led
  with quality; that is preserved)
- Uncached-only lists have no `cached` key and keep `resolution > quality`.

The Stable profile's own 4K sort (`output-profile-policy.js`) gets the same
order. The new test `within a 2160p tier a cached WEB-DL beats an uncached
REMUX` fails against the previous order with exactly that symptom.

## 2. `cachedSeries` is emitted

Upstream only splits cached/uncached when both scoped lists exist for the
request type. Series shipped `uncachedSeries` without `cachedSeries`, so the
seeders-promoted uncached order never applied to episodes. `cachedSeries` is a
copy of `series` (which leads with `cached`), so cached episodes sort exactly
as before.

## 3. EZTV / Torrent Galaxy / Knaben / Zilean ship disabled without a torrent debrid service

All four extend upstream `TorznabPreset`, whose `generateAddons` throws
"requires at least one usable service" when no StremThru-supported service is
enabled. Config create/update validates with
`skipErrorsFromAddonsOrProxies: false` (`db/repositories/users.ts`), so one
such enabled preset rejects the whole save. P2P and EasyNews-only builds have
no such service. They are now emitted `enabled: false` there
(`hasTorrentDebridService`), and the generator drops disabled presets before
output, so P2P and EasyNews-only builds leave them out entirely and the save
succeeds. Rebuilding after adding a debrid service brings them back. Affects Advanced too, where the bug was
latent; v3.14's Balanced restoration is what would have exposed it to default
users.

## Fixture diff

Only `sort.*` paths changed in the three TorBox fixtures; `p2p-1080p-free` is
unchanged (the facade's preset list comes from its caller, not from these
fixtures).
